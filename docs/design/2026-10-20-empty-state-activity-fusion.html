    合成一张卡：一个圆角、一个填充、一条描边

    热力图与曲线住进同一个 RoundedRectangle(14)， 填充 primary@5.5%、描边 primary@16%、柔阴影 primary@5%—— 与胶囊卡（12% / 24% / 5.5%）同一族，只是大卡略淡。 中间用 1px primary@14% 竖线分隔，两侧不再是两个控件。

  • 2

    两个图共享同一条 30 天时间基线

    热力图最左列对齐曲线的第一个点、最右列对齐最后一个点，颜色共用同一套 primary 透明度阶梯（8% → 40% → 60% → 80% → 100%）。 一个回答"有没有发生"，一个回答"用了多少"，读起来是同一段时间的两种视图。

  • 3

    删掉设置面板词汇：网格线、坐标轴日期、卡片边框

    空态里的曲线不需要 X/Y 刻度。用一个本地轻量 ActivitySparkline（Canvas 手绘， 无网格、无坐标轴、末点加重），AppLineChart 保持原样继续服务设置页与 HTTP 统计。

  • 4

    一行同源小字，把图形锚住

    「近 30 天 · 62 条对话 · 128K tokens」放在卡片顶部，图标 + 文字的组合与胶囊一致。 它取代两块图各自的 caption——只有一行，不构成噪声，同时把数字还给用户。

  • 5

    左右边界与胶囊流完全对齐

    卡片宽度取 520，与 PromptSuggestionFlow 的 520 同一基准， 居中。中部与底部共用同一条左右边界，这是"同一个页面"的第一个视觉信号。

  • 6

    接缝与底色

    给空态 item 设 showsTrailingDivider: false 去掉那条系统分隔线； 同时把氛围渐变的中心从 42% 下移到 50%、半径放大，让雾气自然覆盖到底部卡片区域。 图表区与输入框之间的分隔线保留——那是真正的功能分区。

为什么仍然留在 bottomFixed 槽位？ 活动条现在是独立底栏，是因为空态内容在 ScrollView 里居中，矮窗口时页脚会被推出视口。 融合不靠"把两块图搬进中间的内容流"，而靠去掉接缝 + 同源样式 + 同一左右基准—— 这样既保住矮窗口下的可见性，也不破坏底栏语义。

3 · 备选方案

如果 A 方案的改动量太大，可以按 B / C 逐级落地；两者互不冲突，可叠加。

Option B · 最小改动

只做去缝 + 同色

不动布局槽位、不换组件，只做三件事，拿到约七成收益。

  • 去掉 stack 与 bottomFixed 之间的 AppDivider()
  • 热力图与折线图包进同一个圆角容器，共用填充与描边
  • 折线图隐藏网格线与坐标轴日期（给 AppLineChart 加 showsGrid / showsAxisLabels 开关，默认值保持现状）

代价：底部与中部仍是两个区域，"接缝"只是被弱化而非消失；卡片宽度仍是 620 而非 520。

Option C · 复合图

日历 + 曲线叠成一张图

把热力图的 30 个格子当作 x 轴底座，曲线直接浮在格子正上方，共用一条时间轴与一个边框。

  • 融合度最高：读者一眼看到"哪天发生了什么、消耗多少"
  • 卡片更矮（约 76pt），比并排方案省约 30pt 高度
  • 需要精确对位，窗口变窄时曲线与格子容易糊在一起

适合作为 A 方案落地稳定后的第二阶段，而不是第一步。
