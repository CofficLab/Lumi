# 重构：抽取 MessageStreamingStore，分离流式状态与 UI

## 目标
把当前散落在 `MessageListView` 里的流式临时行生命周期管理（start/delta/end、临时行 append/patch/清理、refreshTail 防重复逻辑）抽到 kernel 的独立服务 `MessageStreamingStore`（`@MainActor ObservableObject`）。UI 只负责读 store 并在渲染时把临时行拼接到 `messages` 末尾，彻底分离"持久化历史"与"实时流式"两种语义。

**预期收益**：MessageListView 瘦身约 80 行（删除 handleStreaming / refreshTail 流式分支 / streamingMessageID 全套），refreshTail 的复杂防重复逻辑消失，流式与数据库语义再也不会打架。

## 决策（已确认）
- 新建独立 `MessageStreamingStore`，不塞进现有 Manager
- 一次性切换，删除旧的 `.lumiMessageStreaming` Notification 通道
- 临时行用**进程级稳定常量 id**（与落库行 id 永不冲突，UI 拼接零去重）
- store 不分页、不查库，只持有"当前正在流式的那一条"

## 第 1 步：kernel 新增 MessageStreaming 协议 + 注册（LumiKernel 包）

### A. 新建 `Packages/LumiKernel/Sources/LumiKernel/Providers/MessageStreaming.swift`
```swift
import Combine
import Foundation

/// 流式输出能力协议（runner 写、UI 读）。
/// 持有"当前正在流式的临时 assistant 行"，全程不查库。
/// 临时行用稳定常量 id，与最终落库行 id 永不冲突，UI 拼接时无需去重。
@MainActor
public protocol MessageStreaming: ObservableObject where ObjectWillChangePublisher == ObservableObjectPublisher {
    /// 当前正在流式的临时行（最多一条）。非 nil 时 UI 把它拼到 messages 末尾渲染。
    var currentStreamingRow: LumiChatMessage? { get }

    /// 开始一次流式：创建一条空临时行（稳定 id）。
    func startStreaming(conversationID: UUID) async

    /// 追加正文增量，更新临时行 content。
    func appendContent(_ piece: String) async

    /// 追加思考增量，更新临时行 reasoningContent。
    func appendThinking(_ piece: String) async

    /// 结束流式：清空临时行（落库行由 UI 的 messagesDidChange 自然刷新显示）。
    func endStreaming() async
}

public extension MessageStreaming {
    /// 临时行使用的进程级稳定 id，永不与任何落库消息冲突。
    static var streamingRowID: UUID { Self._streamingRowID }
    fileprivate static let _streamingRowID = UUID()
}
```

> 说明：临时行用 `Self.streamingRowID`（进程级常量），同一次会话内稳定不变，SwiftUI diff 稳定。切换"临时行 → 落库行"时 id 变了，但流式行通常在列表底部，视觉影响极小。

### B. `LumiKernel+Registration.swift` 末尾加注册方法（照 registerMessageSend 模板）
```swift
public func registerMessageStreaming(_ streaming: any MessageStreaming) throws {
    try registerService(MessageStreaming.self, streaming)
}
```

### C. `LumiKernel+Services.swift` 加计算属性
```swift
public var messageStreaming: (any MessageStreaming)? {
    resolveService(MessageStreaming.self)
}
```
（不加入 startup 必需服务校验——它是可选增强服务，缺失时 UI 优雅降级为不显示流式。）

## 第 2 步：实现 MessageStreamingStore（新建插件 MessageStreamingPlugin）

照 `MessageSenderPlugin` 结构新建插件 `Plugins/MessageStreamingPlugin/`：
- `Package.swift`（依赖 LumiKernel）
- `Sources/MessageStreamingPlugin/MessageStreamingPlugin.swift`：onBoot 里 `MessageStreamingStore(kernel:)` + `kernel.registerMessageStreaming(store)`，order 设大（如 60，在 MessageStore/MessageSender 之前，确保 UI 读时已就绪）
- `Sources/MessageStreamingPlugin/MessageStreamingStore.swift`：
```swift
@MainActor
public final class MessageStreamingStore: MessageStreaming {
    @Published public private(set) var currentStreamingRow: LumiChatMessage?
    private var conversationID: UUID?

    public init(kernel: LumiKernel) {}

    public func startStreaming(conversationID: UUID) async {
        self.conversationID = conversationID
        currentStreamingRow = LumiChatMessage(
            id: Self.streamingRowID,
            conversationID: conversationID,
            role: .assistant,
            content: ""
        )
    }
    public func appendContent(_ piece: String) async {
        guard var row = currentStreamingRow, !piece.isEmpty else { return }
        row.content += piece
        currentStreamingRow = row
    }
    public func appendThinking(_ piece: String) async {
        guard var row = currentStreamingRow, !piece.isEmpty else { return }
        row.reasoningContent = (row.reasoningContent ?? "") + piece
        currentStreamingRow = row
    }
    public func endStreaming() async {
        currentStreamingRow = nil
        conversationID = nil
    }
}
```
> 在根 `Package.swift` / Xcode 项目里把新插件作为 local package 加入（参考其他插件的接入方式）。

## 第 3 步：AgentTurnRunner 改写——从发 Notification 改为写 store

修改 `Plugins/AgentTurnRunnerPlugin/Sources/.../Services/AgentTurnRunner.swift`：

**(a) 删除** `StreamingChunkState` actor（整个）——累积职责移入 store。

**(b) `executeTurnLoop` 流式段（约 335-400 行）改写**：
- 删掉 `assistantID = UUID()` 和 `postMessageStreaming(kind: .start ...)` —— 改为：
  ```swift
  await kernel.messageStreaming?.startStreaming(conversationID: conversationID)
  ```
- onChunk 里删掉 `state` 累积，直接调 store：
  ```swift
  if chunk.isThinking { await store?.appendThinking(chunk.content ?? "") }
  else { await store?.appendContent(chunk.content ?? "") }
  ```
  （其中 `store = kernel.messageStreaming`，在循环外取一次）
- catch 里删 `postMessageStreaming(kind: .end ...)` —— 改为 `await kernel.messageStreaming?.endStreaming()`

**(c) 最终消息落库**：`finalizedMessage` **不再用预生成 assistantID 重建**（临时行已是独立稳定 id，无需对齐）。直接 `insertMessage(assistantMessage, to: conversationID)`，然后 `await kernel.messageStreaming?.endStreaming()` 清掉临时行。落库触发的 messagesDidChange 让真实行进 messages。

## 第 4 步：MessageListView 瘦身——删除流式状态管理，改为读 store

修改 `Plugins/MessageListPlugin/Sources/Views/MessageListView.swift`：

**(a) 删除**：
- `@State private var streamingMessageID: UUID?`（及其所有引用：切会话清理、handleStreaming、refreshTail）
- 整个 `handleStreaming(...)` 方法
- `onReceive(.lumiMessageStreaming)` 订阅

**(b) refreshTail 删除流式分支**：删掉"摘出临时行 / 判断 alreadyPersisted / 挂回 / 兜底去重"整段（约 255-291 行）。refreshTail 回归纯粹的"查最近一页 + overlap 合并"。

**(c) displayMessages 改为拼接临时行**（复用现有 status 拼接模式）：
```swift
private var displayMessages: [LumiChatMessage] {
    guard let conversationID = selectedConversationID else { return messages }
    var rows = messages
    // 流式临时行（独立稳定 id，永不与落库行冲突，零去重）
    if let streamingRow = kernel.messageStreaming?.currentStreamingRow,
       streamingRow.conversationID == conversationID {
        rows.append(streamingRow)
    }
    // "正在发送中"状态行（沿用现有逻辑）
    if isSending {
        rows.append(/* 现有 statusMessage */)
    }
    return rows
}
```

**(d) 流式跟随滚动**：store 是 ObservableObject，通过 kernel 自动转发 objectWillChange，UI 已感知变化重渲染。滚动跟随用 `.onChange(of: kernel.messageStreaming?.currentStreamingRow?.content)`（或 monitor streamingRow 存在性）触发：
```swift
.onChange(of: kernel.messageStreaming?.currentStreamingRow) { _ in
    if isAtBottom { proxy.scrollTo(Self.bottomAnchorID, anchor: .bottom) }  // 无动画
}
```

## 关键风险与取舍（如实说明）
1. **临时行→落库行切换的 id 变化**：因用独立稳定 id，切换时 SwiftUI 视为"旧行消失/新行出现"。但流式行在列表底部，且落库几乎是瞬时的，视觉上至多一次极轻微的重排，可接受。若实测闪烁明显，可在 displayMessages 拼接处做"store 行存在则不显示同会话最新落库行"的临时遮罩——但这属于优化，非必需。
2. **新插件接入 Xcode 项目**：需确认根项目如何引用 local plugin package（参考现有插件），漏接入会导致 store 永不注册、UI 优雅降级为无流式。
3. **store 的并发安全**：所有写方法标 async，从 onChunk（后台线程）`await` 调用，跳回 @MainActor 执行，沿用现有 emitDelta 模式，线程安全。
