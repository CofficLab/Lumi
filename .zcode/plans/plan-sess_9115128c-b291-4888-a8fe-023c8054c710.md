## 目标
删除 `LayoutState` 类，把其全部状态与行为内联进 `LayoutManager`（`WorkspaceProviding` 的实现类）。消除一层 Combine 转发（当前 `LayoutManager` 订阅 `layoutState.objectWillChange` 再 re-emit），减少"信号丢失导致 UI 不刷新"的隐患（即 ActivityBar 激活不切换那类 bug 的温床）。`LayoutStateInfo`（DTO）与 `VisibilityFlags` 保留不动。

## 设计要点
- `LayoutManager` 本就是 `@MainActor final class ... : ObservableObject`。`LayoutState` 的所有 `@Published` 属性原样搬到 `LayoutManager`，`objectWillChange` 天然连通 kernel→视图，不再需要转发订阅。
- 持久化订阅（debounce 0.3s 落盘）从订阅 `layoutState.objectWillChange` 改为订阅自身 `objectWillChange`，行为不变。
- 回填"首个激活容器"采用方案 B：下沉进 `registerViewContainer`，并用 `activeViewContainerID == nil` 守卫保证只赋值一次（持久化恢复值优先，不受影响）。
- `LayoutSettingsView` 改走协议访问器（不再读 `.layoutState`），为此给 `WorkspaceProviding` 补 4 个只读 getter。

## 分步实施（每步独立可编译）

### Step 1 — 协议补访问器 + 迁移 LayoutSettingsView（准备）
- `WorkspaceProviding.swift`：新增 4 个只读要求
  - `func storedRailDivider(for viewContainerID: String) -> CGFloat?`
  - `func storedChatSectionDivider(for viewContainerID: String, layout: LumiChatSectionLayout) -> CGFloat?`
  - `func storedBottomPanelDivider(for viewContainerID: String) -> CGFloat?`
  - `func visibilityOverride(for containerID: String) -> VisibilityFlags?`
- `LayoutManager.swift`：实现这 4 个（暂时仍转发 `layoutState.X`，因为此时 LayoutState 还在）。
- `LayoutSettingsView.swift`：删除 `private var layoutState: LayoutState?`（25-27 行）；把 245/273/275/284-290 行的 `layoutState?.X` 全部改为 `kernel.workspace?.X`。tabsSection/dividersSection 里的 `let state = layoutState` 改为 `let state = kernel.workspace`。
- 结果：`WorkspaceProviding.layoutState` 已无外部读者。

### Step 2 — 删除死代码（准备）
- 删除整个 `Packages/LumiKernel/Sources/LumiKernel/Types/Layout/SplitDividerRole.swift`（`SplitDividerRole`/`SplitDividerAccess`/`makeAccess` 零引用）。
- 删除 `Plugins/EditorSwiftPlugin/Sources/Support/PreviewEditorSwiftSupport.swift`（被 `Package.swift` 的 `exclude:` 排除，从不参与编译，且引用已删除的类型）。
- （可选）修正 `Plugins/GitPlugin/Sources/Views/GitCommitDetailView.swift:17` 注释中对 `LayoutState` 的过时引用。

### Step 3 — 回填逻辑下沉进 registerViewContainer（准备）
- `LayoutState.registerViewContainer`（LayoutStateTypes.swift:343）：在 `updateSortedViewContainers()` 之后追加：
  ```swift
  if activeViewContainerID == nil, sortedViewContainers.first?.id == container.id {
      activeViewContainerID = container.id
  }
  ```
- `PluginManager.swift`：删除 296-302 行的 `first.id` 赋值块；保留 304-317 行的 `applyVisibility` 块。
- 结果：内核 `PluginManager` 不再触碰 `layoutState`。

### Step 4 — 合并（原子步骤，整组一起改才编译）
- **`LayoutManager.swift`**：
  - 移植 `LayoutState` 全部存储属性（带 `@Published`/`didSet`/`private` 修饰原样保留）、`init` 默认值（`defaultRailDivider` 等改为内联默认值）、全部方法（`activateContainer`/`applyResolvedVisibility`/`applyVisibility`/`viewContainer`/`updateSortedViewContainers`/各 divider/tab/restore 方法等），所有 `layoutState.X` → `X`，`Self.t`/`Self.logger`/`Self.verbose` 改用 LayoutManager 自己的。
  - 删除 `public let layoutState: LayoutState`、`layoutStateSubscription`。
  - `persistenceSubscription` 改为订阅 `objectWillChange.debounce(0.3).sink { saveState() }`。
  - 原有 ~20 个转发方法（136-254 行）变成真实实现（多数只是去掉 `layoutState.` 前缀），保留作为 `WorkspaceProviding` 协议实现。
  - UI 贡献相关方法（titleToolbar/chatSection/statusBar/... 及其 `objectWillChange.send()`）原样保留。
- **`LayoutStateTypes.swift`**：删除 `LayoutState` 类（约 103-561 行）；保留文件顶部的 `LayoutStateInfo`（1-73）与 `VisibilityFlags`（78-101）。
- **`WorkspaceProviding.swift`**：删除 `var layoutState: LayoutState { get }`（14-15 行）。
- **`OnBoot.swift`**：9 处 `manager.layoutState.X` → `manager.X`（28/30-34/37/40/43 行）。
